02系统架构分层（模块化单体）

不拆微服务；模块间只能经 service 层调用，禁止跨模块直改表——这是「企业级单人可控」的关键约束。橙色高亮 = 本项目新增。

接入层Vue 3 + TS + Element Plus + ECharts
仓储/单据工作台BI 驾驶舱财务菜单域凭证/报表页ChatBI 面板票据确认页
接口层FastAPI + Pydantic v2
统一响应/异常鉴权 RBAC/accounting/*/ai/*（可整开关停用）
业务域已有进销存底座，直接复用
商品/客户仓库→库区→库位批次/效期入库/出库/波次退货/移库/盘点采购（Phase 2）
财务域 ⭐本项目核心增量
科目表 COA凭证状态机期间/结账凭证引擎（规则表驱动）余额表/试算平衡利润表/资产负债表应收/核销（升级挂分录）
AI 域可选模块，核心 ERP 不依赖它
LlmClient 适配ai_draft 草稿机制ChatBI 语义视图票据多模态解析审计 Agent（只读）
数据层PostgreSQL 16 生产 / SQLite 开发（MySQL 8 兼容选项）
SQLAlchemy 2.0Alembic 版本化迁移行级锁 SELECT FOR UPDATE整单事务全量流水

🔒 横切：一致性

业务确认与凭证生成同事务；失败整单回滚。幂等键防重复入账。

🧾 横切：不可篡改

凭证只追加；更正走红字冲销；closed 期间拒写；全量审计日志。

🇨🇳 横切：本地化

管理会计口径定位；不做税务申报（Non-Goals 硬边界，README 声明）。

📦 横切：私有化

AI 可切 Ollama 全离线；也可整体停用 AI，核心功能零影响。

03核心链路：业务事件 → 凭证 → 报表

「业财一体」不是库存+记账两个模块，而是下面这条自动转化链路。规则（科目映射/借贷模板）全部存配置表，管理员可改，零代码扩展新事件。

销售侧链路 Phase 1

销售订单SO-… · DRAFT → CONFIRMED → SHIPPED
↓ 事件 SALE_SHIPPED
凭证引擎 generate_voucher()读 posting_rule → 套借贷模板 → 平衡校验 → 同事务落凭证（幂等）
↓
凭证：发货确认收入 + 结转成本借 应收账款 112201 / 主营业务成本 6401贷 主营业务收入 6001 / 存货 1405
↓ 事件 RECEIVE_SETTLED（收款核销）
收款核销 → 凭证借 银行存款 1002贷 应收账款 112201 · 更新账龄

采购侧链路 Phase 2

采购订单 → 采购入库PO / PI · 状态机驱动，批次入库
↓ 事件 PURCHASE_RECEIVED
凭证引擎（同一套规则机制）新增事件只是新增规则行，引擎代码不动
↓
凭证：入库暂估借 存货 1405贷 应付账款-暂估 220202
↓ 发票到达 → 付款核销
应付 → 付款凭证借 应付账款 220201贷 银行存款 1002
∑
期末：所有已过账凭证 → 科目余额表 → 试算平衡 → 利润表 / 资产负债表
不变量（自动测试断言）：有借必有贷、借贷必相等；资产 = 负债 + 所有者权益。

04AI 能力与安全边界（人机协同范式）

AI 是效率层，不是记账主体。「AI 永不直接写财务数据」是产品级承诺，也是本项目的面试/社区谈资。

① 触发场景

ChatBI 提问 / 上传发票图片 / 月末体检任务

→

② LlmClient 适配层

OpenAI 兼容协议，配置即切换 DeepSeek / Kimi / Ollama；记录 ai_audit_log

→

③ 产出落 ai_draft

结构化 payload + 置信度 + 生成依据；72h 未确认自动过期

→

④ 人工确认页

渲染成可编辑表单，低置信字段高亮，歧义匹配必须人工二选一

→

⑤ 业务 service 生效

经凭证引擎校验（平衡/期间开放）正式落库，source_draft_id 全程可追溯

✕ 禁止路径：LLM 输出 → 直写 finance/accounting 数据表。ChatBI 也不做裸 text-to-sql，只允许在白名单语义视图（销售毛利/应收账龄/库存快照）内生成受约束查询计划，越界即拒答。

05财务内核领域模型（2.1 已落地）

对应 backend-python/app/models/accounting.py，4 张表构成会计底座；Phase 1 后续任务再加 3 张凭证引擎配置表。

Account 会计科目
  • PKid
  • UKcode · 如 2202 / 220201
  • ·name / level / status
  • ·category · ASSET…EXPENSE
  • ·direction · DEBIT / CREDIT
  • FKparent_id · 自关联树
  • ·is_leaf · 仅明细可记账
  • ·aux_dimensions · 客户/供应商/仓
Voucher 记账凭证
  • PKid
  • UKvoucher_no · JV-YYYYMMDD-XXX
  • ·voucher_date / memo
  • FKperiod_code · 2026-09
  • SMstatus · DRAFT→POSTED→REVERSED
  • ·source_type · MANUAL/ENGINE/AI
  • ·reverses_voucher_no ⇄ 双向关联
  • ·reversed_voucher_no
VoucherLine 凭证分录
  • PKid
  • FKvoucher_id + seq · 行内唯一
  • FKaccount_id · 必须明细科目
  • ·direction · D 借 / C 贷
  • ·amount · 负数即红字冲销
  • ·aux_type / aux_id / aux_name
  • ·memo
Period 会计期间
  • PKid
  • UKcode · 自然月 YYYY-MM
  • ·start_date / end_date
  • SMstatus · OPEN / CLOSED
  • ·closed_at · 结账留痕
  • ·closed 期间凭证写入 → 409
  • ·反结账必须倒序 + 审计日志
Account 1 ─ N Account（科目树，挂子自动置非明细） Voucher 1 ─ N VoucherLine（级联删除，仅草稿可改） VoucherLine N ─ 1 Account Voucher N ─ 1 Period（按 period_code 聚合）
