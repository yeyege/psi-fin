## 1. 产品概述

### 1.1 背景与问题

中小企业（贸易/零售/仓储类）普遍存在「业务账」与「财务账」两张皮：库存系统记数量、财务软件记金额，两边靠人工月底对账。市面开源 ERP 要么财务模块形同虚设（只有流水没有凭证与总账），要么体量过重难以私有化，且几乎没有可用的 AI 能力。

本项目在已建成的 WMS（批次库存 / 出入库 / 波次 / 盘点，126 个测试用例）之上补齐财务核算内核与 AI 能力，形成**可一键私有化部署的「进销存 + 财务核算 + AI 助手」一体化开源系统**。

### 1.2 产品定位（一句话）

> 任何业务单据，经规则驱动的凭证引擎自动生成财务凭证，实时进利润表与资产负债表。

- 定位口径：**管理会计 / 内部核算**——服务于经营者看懂经营状况，**不是**报税报账用的合规财务软件（见 2.2 边界）
- 交付形态：开源代码 + Docker Compose 一键部署 + 纯前端 Mock 演示站

### 1.3 目标用户与角色权限

| 角色 | 典型诉求 | 基础数据 | 仓储单据 | 销售/采购 | 财务凭证/报表 | 过账/结账 | AI 功能 | 系统管理 |
|---|---|---|---|---|---|---|---|---|
| 管理员 admin | 落地实施、配置规则 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 财务会计 | 凭证、核销、结账、审票 | 只读 | 只读 | 只读 | ✅ | ✅ | 确认权 | ❌ |
| 仓库作业员 | 出入库、拣货、盘点 | 只读 | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| 老板/经营层 | 看报表与驾驶舱 | 只读 | 只读 | 只读 | 只读 | ❌ | ChatBI | ❌ |

权限沿用现有自研认证（用户名口令 + Token + role），本期扩财务类权限点；不做 OAuth/SSO（Non-Goals）。

### 1.4 核心使用场景（用户故事）

1. **发货即入账**：仓管员确认出库 → 系统自动生成「借应收 / 贷收入」「借成本 / 贷存货」凭证并过账 → 老板刷新利润表立刻看到数变化。若凭证生成失败，整笔发货回滚，杜绝业务与财务两张皮。
2. **收款核销**：财务登记收款、核销到应收（支持部分核销/预收）→ 自动生成「借银行 / 贷应收」凭证 → 账龄表同步刷新。
3. **采购到付款**：采购入库生成暂估凭证，发票到达、付款核销各生成对应凭证，全程幂等防重复入账。
4. **月末结账**：系统检查试算平衡与草稿残留 → 一键结转损益生成转账凭证 → 锁定期间，之后任何人补录该期间凭证被拒绝；发现错误只能在开放期间红字冲销重做。
5. **AI 问数**：老板问「上月各仓库销售毛利排名前 5」→ 系统在白名单语义视图内解析并返回条形图 + 口径说明；点击柱子可继续追问。
6. **票据入账**：会计拍一张费用发票 → 模型解析要素生成草稿凭证（低置信字段高亮、往来单位歧义必选）→ 人工修正后确认入账，原票据与解析依据永久挂在凭证上。

## 2. 范围与边界

### 2.1 本期范围（对应 4 个阶段，见第 6 节里程碑）

- 财务域：科目表、凭证、期间结账、凭证引擎、余额表/两大报表、成本口径、结转损益
- 业务域补全：采购订单/入库/应付/付款、费用单
- AI 域：LLM 适配平台层、ChatBI、票据识别入账
- 工程基建：Alembic 迁移、PostgreSQL 主库、CI 双数据库轨、覆盖率、可观测性最小集、开源门面

### 2.2 Non-Goals（明确不做，防止范围失控）

| 不做 | 原因 |
|---|---|
| 税务申报、发票认证、金税对接 | 合规风险与产品定位（管理会计）不符，README 显式声明 |
| 生产制造、多币种、合并报表、预算 | 目标客户（中小贸易/仓储）不需要 |
| 微服务拆分、多租户 SaaS 化 | 单人可维护优先；模块化单体，字段预留 tenant_id |
| AI 自动过账 | 安全边界：AI 一切写操作必须人工确认 |
| OAuth/SSO、移动端 App | 演示级鉴权够用；响应式 Web 覆盖移动查看 |
| Celery/Redis 任务队列（v1） | 与运维成本不匹配，长任务用异步 HTTP + SSE 承接 |

### 3.2 财务域（核心增量）

| 编号 | 需求 | 优先级 | 状态 | 说明与验收标准 |

| FR-FIN-02 | 记账凭证管理 | P0 | 🔶 | 状态机 草稿→过账→已冲销；过账强制借贷平衡且至少两条分录；已过账禁改删（409），更正走红字冲销且新旧凭证双向单号关联；凭证号**按会计期间连续编号**（JV-202609-001），关闭期间号段封存。**模型/状态机/冲销已完成，录入界面待交付** |
| FR-FIN-03 | 会计期间与结账 | P0 | 🔶 | 自然月期间；结账前检查未过账草稿与试算平衡；已锁期间一切凭证写入拒绝（409）；反结账仅允许倒序且留审计日志。**服务层已完成，界面待交付** |

### 3.3 AI 域（可选模块，核心系统不依赖）

| 编号 | 需求 | 优先级 | 状态 | 说明与验收标准 |
|---|---|---|---|---|
| FR-AI-01 | AI 平台层 | P0 | ⬜ | 统一 LLM 适配（OpenAI 兼容协议，配置即切 DeepSeek/Kimi/Ollama），带超时/重试；`AI_ENABLED` 总开关，关闭后核心功能零影响（AI 路由 503）；通用「AI 草稿→人工确认」框架：草稿含 payload/置信度/生成依据，72h 未确认自动过期，确认后正式记录回写 source_draft_id；每次调用记审计（场景/模型/耗时/token 成本）并有用量页 |
| FR-AI-02 | ChatBI 问数 | P0 | ⬜ | **不做任意 SQL**：LLM 仅在白名单语义视图（销售毛利/应收账龄/库存快照）内输出受 JSON Schema 约束的查询计划，后端参数化模板执行；无匹配主题明确拒答并列出可查范围；多轮会话继承时间/维度上下文；结果图表化（ECharts）+ 口径说明 + 点击图表元素预填追问；流式返回降低感知延迟 |
| FR-AI-03 | 票据识别入账 | P1 | ⬜ | 上传发票/银行回单（≤10MB）→ 视觉模型解析要素（类型/日期/往来单位/金额三件套）→ 草稿凭证确认页：字段+置信度展示、低置信高亮、必填缺失禁确认；往来单位模糊匹配，**歧义必须人工选择，不自动猜**；确认后经引擎校验过账，原票据图片与解析依据可永久反查 |
| FR-AI-04 | 异常审计 Agent | P2 | ⬜ | 月末只读扫描凭证与库存流水，检出科目误用/期末大额调账/借贷异常模式，产出带理由的体检报告；注入 5 类典型异常样例召回 100%，误报人工复核 |

**AI 安全红线（产品级承诺，写入 README）**：系统内不存在任何「模型输出直接写业务/财务表」的代码路径；AI 全部产出走草稿，人是记账主体。

## 4. 非功能需求

| 编号 | 类别 | 要求 | 验收方式 |
|---|---|---|---|
| NFR-01 | 一致性 | 业务确认与凭证生成原子（同事务整单回滚）；事件幂等；行级锁防并发重复入账；事务隔离级别统一 READ COMMITTED | 并发专测在 PostgreSQL 真实库轨执行（SQLite 轨跳过），CI 保证该类用例收集数 > 0 |
| NFR-02 | 不可篡改 | 已过账凭证只追加；红字冲销代替修改；关账拒写；关键操作留痕 | 状态机用例 + 409 断言 |
| NFR-03 | 金额精度 | 财务域金额一律数值精度 2 位小数的精确类型（Numeric(18,2)+Decimal），**禁止浮点**；借贷平衡用精确比较 | 「0.1+0.2=0.3」类断言；代码扫描禁 Float 金额 |
| NFR-04 | 性能 | 3000 单据量级下：报表查询 ≤ 2s；列表接口 ≤ 500ms；ChatBI 端到端 ≤ 15s（流式首包 ≤ 3s） | 演示数据集上实测记录在 docs |
| NFR-05 | 安全 | 查询一律参数化；ChatBI 白名单语义层；AI 出站调用超时与重试上限；凭证/票据附件访问受权限控制；演示站仅纯前端 Mock 不触真实数据 | 用例 + 人工渗透自查清单 |
| NFR-06 | 兼容性 | 数据库三态：开发/测试 SQLite、生产主库 PostgreSQL 16、兼容 MySQL 8.0（同一套 ORM 代码可移植，迁移脚本双库可跑）；现代浏览器 | CI 双轨（PG 主流 + MySQL nightly） |
| NFR-07 | 可维护性 | 数据库变更一律版本化迁移（模型与迁移漂移检测进 CI）；模块间只经 service 层调用、禁止跨模块直改表；覆盖率基线只升不降 | CI 红/绿即证 |
| NFR-08 | 可用性 | 新机器按 README 10 分钟完成部署并看到演示数据 | 冷启动演练一次并记录耗时 |

## 5. 数据与口径约定

- **凭证号**：`JV-{yyyyMM}-{seq}`，按期间连续；容忍断号、不容忍错序
- **期间**：自然月，`YYYY-MM`；凭证按凭证日期归属期间（期间自动建档、锁定后不再重开）
- **金额**：财务域 Numeric(18,2)+Decimal；存量业务表（财务流水等）暂为浮点演示口径，财务引擎接入该单据时在边界统一转换为 Decimal 记账，两套口径转换点写入架构文档
- **演示数据**：全部生成器 seeded 可复现；标准核对案例（10 笔典型业务的手工编制凭证与报表答案）随 seed 发布，用于自证报表正确性
- **成本**：库存流水为成本唯一来源；报表口径为移动加权平均，与批次 FIFO 效期管理的口径差异在文档说明

## 9. 术语表

| 术语 | 释义 |
|---|---|
| 业财一体化 | 业务单据经规则自动转化为财务凭证，业务流与资金流同源 |
| 凭证引擎 | 读「过账规则配置表」把业务事件翻译为借贷分录的服务 |
| 明细科目（is_leaf） | 允许挂账的唯一科目层级；有下级的科目仅作汇总 |
| 辅助核算 | 在科目之外按客户/供应商/仓库维度记账，用于账龄、毛利等分析 |
| 红字冲销 | 以负数金额的镜像凭证抵销原凭证，替代修改/删除，保证可审计 |
| 结账/锁账 | 期间封存：该期间凭证写入一律拒绝，错误只能在开放期间冲销重做 |
| 试算平衡 | 全部科目借方累计=贷方累计；资产负债表两侧恒等的底层保证 |
| 语义视图 | 为 ChatBI 预定义的只读宽表视图，AI 只能在其中受控查询 |
