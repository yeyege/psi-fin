# platform/positioning Specification

## Purpose
让系统对外呈现为「进销存 + 业财一体中后台」,而不是一套单纯的仓储系统,使销售、库存、财务三块在同一个中后台里各归其位。

## Requirements

### Requirement: 系统定位与导航分组

系统的页面标题与侧边导航 SHALL 体现中后台定位,并 SHALL 按业务域分组呈现,至少包含:经营驾驶舱、销售、库存、财务、基础数据、系统管理等分组。

#### Scenario: 查看导航结构

- **WHEN** 用户登录后打开主界面
- **THEN** 侧边导航按业务域分组展示,可看到经营驾驶舱、销售、库存、财务等分组

### Requirement: 既有功能可达

重定位后,原有全部功能页面 SHALL 仍然可达,归入对应板块(库存作业、基础数据、系统管理等),不得因分组调整而丢失入口。

#### Scenario: 访问原有页面

- **WHEN** 用户依次点击原有出入库、波次、盘点、商品、客户、仓库、用户等菜单
- **THEN** 每个页面均能正常打开,功能与重定位前一致

### Requirement: 项目说明同步更新

项目 README SHALL 更新首段定位描述,说明本系统为「进销存 + 业财一体中后台」,并简述"业务单据 → 财务记录"的闭环。

#### Scenario: 阅读 README

- **WHEN** 打开 README 首段
- **THEN** 能看到中后台定位与业财闭环说明,而非仅描述为 WMS

### Requirement: 视觉与交互一致

新增的销售、财务、驾驶舱页面 SHALL 沿用既有页面的布局与组件风格(Element Plus + 同一套页面结构),保持整体一致。

#### Scenario: 页面风格一致

- **WHEN** 在库存页面与新增财务页面之间切换
- **THEN** 布局、表格、按钮与配色风格保持一致,无明显割裂
