## Why

当前 WMS 项目已具备「进销存 + 半条业财链路」：销售订单 → 发货生成应收 → 收款核销（部分核销/预收）→ 账龄分析 → 经营驾驶舱，并沉淀了 112 个 pytest 用例、Playwright E2E、CI/CD、Pages 演示站等工程资产。但距离「企业级业财一体化开源项目」仍缺三块：

1. **财务内核缺失**：没有科目表（COA）、记账凭证、总账、期间管理，应收核销只是业务流水而非会计语言，无法出具资产负债表/利润表；
2. **业财联动是硬编码**：发货生应收的逻辑写死在 service 里，没有可扩展的「业务事件 → 会计分录」凭证引擎；
3. **AI 能力为零**：BI 驾驶舱是固定图表，无自然语言问数、无票据识别、无人机协同流程。

目标是将本项目升级为**面向中小企业的「进销存 + 财务核算 + AI 助手」一体化开源 ERP**，可私有化部署。核心差异化卖点是：任何业务单据通过规则驱动的凭证引擎自动生成财务凭证（真·业财闭环），且 AI 全部走「草稿 → 人工确认 → 生效」的安全边界。

## What Changes

- **财务域（新增）**：会计科目表、记账凭证（只追加、红字冲销）、期间与结账锁账、期末结转损益
- **凭证引擎（新增，核心）**：规则表驱动的过账引擎，`事件类型 + 借贷模板 + 科目映射` 全部配置化；首批打通 3 个事件：发货确认应收、收款核销、采购入库暂估
- **报表域（新增）**：利润表、资产负债表（从凭证分录汇总生成），期间追溯
- **业务链补全**：采购域 + 应付、费用单；成本核算改移动加权平均并与批次库存联动
- **AI 平台层（新增）**：LLM 适配器（OpenAI 兼容接口 / Ollama 本地模型），统一的「AI 草稿 → 人工确认」机制；AI 永不直接写财务数据
- **AI 场景一 ChatBI**：自然语言问数，走白名单语义层视图（非裸 text-to-sql），结果以 ECharts 渲染并可下钻
- **AI 场景二 票据入账**：上传发票/银行回单图片 → 多模态模型识别 → 生成草稿凭证 → 会计确认后入账
- **开源门面**：License 定版（Apache-2.0）、docs/ 架构文档（凭证引擎设计单独成篇）、一键 seed 演示数据（可复现）、README 挂覆盖率徽章、每阶段 Release + 演示站更新

## Capabilities

### New Capabilities
- `finance/accounting-core`：会计内核 — 科目表、凭证生命周期（草稿/过账/冲销）、期间管理与结账锁定
- `finance/voucher-engine`：凭证引擎 — 业务事件规则表、借贷平衡校验、生成幂等性、与业务单据同事务原子性
- `finance/statements`：财务报表 — 利润表、资产负债表、期间选择与追溯
- `ai/platform`：AI 平台层 — LLM 适配器、模型配置、AI 草稿确认安全边界、审计留痕
- `ai/chatbi`：ChatBI 问数 — 语义层白名单、自然语言解析、图表化回答、会话上下文
- `ai/invoice-voucher`：票据识别入账 — 图片上传、多模态解析、草稿凭证生成、人工确认闭环

### Modified Capabilities
- `finance/receivable`：收款核销行为升级为「核销同时通过凭证引擎产生会计分录」，原有核销/账龄 API 行为保持向后兼容

## Impact

- **backend-python/**：新增 `app/finance/`（科目/凭证/期间/报表）与 `app/ai/`（适配器/场景）模块；`services/` 中发货、核销、采购入库路径接入凭证引擎；模型层新增约 10 张表
- **frontend-vue/**：新增会计科目、凭证管理、两张报表、ChatBI 对话面板、票据上传确认页等视图；复用现有 BI 驾驶舱与 ECharts 规范
- **仓库结构**：升级为 Monorepo 门面（apps/ + docs/ + examples/），补 LICENSE、CONTRIBUTING、架构文档
- **测试**：财务域要求与库存域同级的用例覆盖（借贷平衡、幂等、锁账拒写均有专测）；新增 AI 场景的 mock LLM 单测 + 确认闭环 E2E
- **不影响**：现有 WMS 仓储/波次/退货等模块行为；已归档 specs 的行为承诺
