## Purpose

让前端在没有后端的环境下也能完整演示收入侧业财闭环:通过构建开关启用后,所有 `/api` 请求由浏览器内本地实现响应,复刻后端关键业务规则并提供内置演示数据,使 GitHub Pages 这类纯静态托管也能展示"能走通"的系统。

## ADDED Requirements

### Requirement: Mock 模式开关

系统 SHALL 提供构建期开关控制是否启用 Mock 模式;启用时所有 `/api` 请求 MUST 由前端本地实现响应且 MUST NOT 发起真实网络请求;未启用时行为与现状一致(请求走 Vite 代理或配置的 API 地址)。开关默认关闭。

#### Scenario: 启用后不发真实请求

- **WHEN** 以 Mock 模式构建并打开站点(后端未启动)
- **THEN** 页面数据正常加载,且浏览器网络面板中不出现对后端 API 的请求

#### Scenario: 未启用时不改变现有行为

- **WHEN** 本地开发未设置该开关
- **THEN** 请求仍发往 `/api`(经 Vite 代理到后端),与改动前一致

### Requirement: 覆盖业财核心接口

Mock 模式 SHALL 至少覆盖以下接口:登录、客户列表、商品列表、销售订单列表/详情/创建、销售订单确认/发货/完成/作废、应收列表、往来账龄、收款登记(含核销)、驾驶舱汇总/欠款排行/账龄分布/趋势。

#### Scenario: 三个新页面可用

- **WHEN** 在 Mock 模式下依次打开 销售订单、财务应收、经营驾驶舱 页面
- **THEN** 三个页面均能正常加载列表与图表数据,无接口错误

### Requirement: 复刻后端关键业务规则

Mock 实现 SHALL 与后端保持同一业务口径:① 只有在**发货**时才生成应收,且同一订单不重复生成;② 收款核销支持部分核销与结清,单张应收禁止超额核销;③ 收款金额可大于核销金额,差额保留为未核销余额(预收)并可再次核销其他应收;④ 账龄**以到期日为基准**分段(未到期 / 逾期 1-30 / 31-60 / 60+);⑤ 驾驶舱金额与应收台账同源一致。

#### Scenario: 发货才生成应收

- **WHEN** 在 Mock 模式下创建订单并确认(尚未发货)
- **THEN** 财务应收列表中不存在该订单的应收;执行发货后列表中出现金额与到期日(发货日+账期)正确的应收

#### Scenario: 幂等

- **WHEN** 对同一订单重复触发发货
- **THEN** 应收数量不变,且重复发货被拒绝或忽略

#### Scenario: 部分核销与预收

- **WHEN** 对应收 1000 登记收款 600 并核销 600
- **THEN** 该应收状态为部分结清、余额 400;再登记收款 1000 仅核销 400 时,剩余 600 可作为预收余额继续核销其他应收

#### Scenario: 超额核销被拒

- **WHEN** 对未结余额为 400 的应收尝试核销 500
- **THEN** 操作被拒绝,金额与状态不变

#### Scenario: 账龄口径

- **WHEN** 查看往来账龄
- **THEN** 各账龄段按到期日划分,且合计等于全部未结应收余额

### Requirement: 内置演示数据

Mock 模式 SHALL 内置一组可重复的演示数据(客户、商品、订单、应收、部分回款),使页面首次打开即有内容可演示;刷新页面后数据 MUST 重置为初始状态,保证演示可重复。

#### Scenario: 首次打开即有数据

- **WHEN** 首次进入经营驾驶舱
- **THEN** 指标卡与图表显示非零演示数据

#### Scenario: 刷新复位

- **WHEN** 演示过程中修改数据后刷新页面
- **THEN** 数据回到初始演示状态

### Requirement: 未覆盖接口兜底

对 Mock 未实现的接口,系统 SHALL 返回结构合法的空结果(列表类返回空分页、其他返回空数据),MUST NOT 抛出未捕获错误导致页面崩溃。

#### Scenario: 访问未覆盖页面

- **WHEN** 在 Mock 模式下打开仅依赖未覆盖接口的旧页面
- **THEN** 页面加载完成且不出现未捕获异常,内容为空态
