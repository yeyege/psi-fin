## Context

见 proposal.md - Why。当前状态:`preview/business-console-plan.html` 已产出并通过本地 http 服务验证(两个页面均 200,浏览器无报错);现有 BI 看板 `preview/apple-store-wms.html` 为 Apple Store 玻璃拟态风格的可交互单文件看板。约束:演示资产须零构建、单文件可打开、可离线讲解大部分内容。

## Goals / Non-Goals

**Goals:**
- 用一份自包含静态页面承载「业财一体中后台方案」的完整讲解结构,数据驱动渲染,便于改文案不改结构。
- 复用既有 BI 看板视觉语言(玻璃拟态、SF 字体、Apple 色板),让"演示页"与"看板效果"看起来是一个体系。
- 让"中后台菜单长什么样"成为可直接点击讲解的核心交互区。

**Non-Goals:**
- 不把方案做成真实可登录的中后台(本 demo 定位为面试方案讲解,不含真实数据与后端)。
- 不做 Chart.js 等图表在本演示页的重绘(看板效果直接内嵌既有 BI 页,避免重复实现)。
- 不引入任何构建、路由或组件框架。

## Decisions

- **单文件自包含 + JS 数据驱动**:HTML/CSS/JS 全内联,七个章节文案与菜单结构放在 JS 常量(`MENU`、链路数组、`ROADMAP`、`FIT`、`PIPELINE`)里,章节由 `render*()` 渲染。
  理由:改招聘话术只需改数据不改布局;直接打开即用。
  备选:模板拼接每章节写死 HTML → 菜单 30+ 模块改文案成本高,放弃。
- **菜单域划分口径固定为业务/财务/系统三层组织的 8 大域**,模块标注"实现类型徽标(表单/流程/聚合表/仪表盘/视图/系统)"并配"业财衔接"字段。
  理由:规格需要可复用的落地口径;徽标即回答"这个模块在低代码上怎么做"。
  备选:按页面/按功能随意分 → 不可作为未来搭建基线,放弃。
- **看板预览用 iframe 内嵌 `apple-store-wms.html` 并保留"新窗口打开"降级**。
  理由:iframe 失效(如 file:// 浏览器限制)时讲解仍可继续;原看板本身已带 CDN 降级逻辑。
  备选:把看板静态改造成本页章节 → 增加体积且重复维护,放弃。
- **视觉体系复用 BI 看板 tokens**:色板、圆角、毛玻璃、字体栈与原看板一致,保持"一份风格"的整体感。

## Risks / Trade-offs

- [文案口径是面试成败关键,属内容风险] → 内容沉淀为 spec + 数据驱动结构,改文案不重构;演示前需人工通读核对该公司 JD 表述。
- [iframe 在部分打开方式下不渲染] → 提供固定"新窗口打开"链接与提示文案,章节内容不依赖 iframe 成败。
- [内嵌看板需联网加载 Chart.js CDN] → 看板自带 3 秒降级标记与占位,断网不抛错;本演示页其余章节完全离线可用。
- [单文件体积随章节增多变大] → 当前规模(纯文本+少量 SVG)可接受;若未来迁移到 frontend-vue 再做组件化拆分。

## Migration Plan

无存量系统需迁移。变更仅涉及 `preview/` 下两个静态文件;回滚策略为保留本 change 前的文件版本(或从 git 恢复),不影响 `frontend-vue/` 与 `backend-python/`。
