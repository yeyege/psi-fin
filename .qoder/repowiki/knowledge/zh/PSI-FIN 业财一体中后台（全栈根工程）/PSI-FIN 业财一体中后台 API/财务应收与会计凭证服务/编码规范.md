- 所有写操作在提交前进行只读预校验，校验失败不产生任何数据库变更，避免 SQLite SAVEPOINT 不可靠导致的中间态。
- 易冲突的单号生成采用 for _ in range(5) 重试 + IntegrityError 捕获回滚的模式，最终抛 BusinessError(409)。
- 金额统一经 `_r()` 或 `round(..., 2)` 保留两位小数，比较时使用 1e-9 / EPS 容差处理浮点误差。
- 业务规则违反统一抛出 `BusinessError` 并携带 HTTP 状态码（如 409 冲突、422 校验失败、404 不存在）。
- 响应体统一包装为 `{code, message, data}` 结构，由路由层组装返回。
- 查询结果通过独立的 `*_response` 函数（如 `order_response`、`entry_response`）将 ORM 对象序列化为前端字段名（驼峰）。
